# UMEDA · 车站漫游

JR 大阪站、阪急大阪梅田站、御堂筋线梅田站、阪神大阪梅田站、谷町线东梅田站、四桥线西梅田站与 JR 北新地站的局部交互样板，使用 TypeScript + Three.js。采用固定正交斜视，验证建筑拆解质感、独立站点楼层阅读与站内跨层路线。

**当前几何与路线为示意，不能用于现场导航。** 已依据参考 PDF 整理楼层归属、主要闸口名称及站台编号，已接入共同米制基底、七站校准及主要地下／二层公共连接；几何仍为近似拟合，设施及门位尚未逐项现场核验。

## 本地运行

需要 Node.js 24 或以上。

```sh
npm install
npm run dev
```

手动打开 <http://127.0.0.1:5173>。开发服务监听 `0.0.0.0:5173`，局域网设备可通过本机的局域网 IP 访问；可用 `PORT` 环境变量覆盖端口。修改 `src/` 后自动重新构建，刷新页面查看；目前不自动刷新浏览器。

Windows PowerShell 若阻止执行 `npm.ps1`，将命令中的 `npm` 换成 `npm.cmd`。

## VS Code 入口

安装依赖后，在“运行和调试”选择 **JR 大阪站 · 启动服务**，按 F5。该配置仅启动服务，不打开浏览器；手动访问上面的地址即可。停止调试会停止此服务。

另有 **JR 大阪站 · 本地预览** 配置，可由用户主动选择，让 VS Code 启动 Chrome。该配置的后台开发任务需要通过“终止任务”或终端 Ctrl+C 停止。两个入口均使用 5173 端口，不要同时启动。

`Ctrl+Shift+B` 构建网页；“运行任务”中还提供风格检查、类型检查和测试入口。

代码使用 TypeScript 四空格缩进、单行单语句和英文方法文档注释。`npm run check:style` 运行 ESLint 和 Stylelint。样式按组件领域维护，浅色和深色主题共用 CSS 语义变量。页面右上角可选择中、日、英语和深色主题。[代码风格](./docs/development/code-style.md) · [国际化维护](./docs/development/i18n.md)

## 交互范围

- 默认七站同图；左侧为“楼层 / 设施”两个 Tab，车站下拉统一负责筛选与聚焦，M16、阪神、T20、Y11、北新地默认选 B1。设施按车站、楼层、类型过滤，具体选择不会反过来改筛选条件。移动端类型可横向滑动；设施定位平滑移到避开面板后的中心，并显示动画立体图钉。
- 阪急首版：1F 公共入口、2F 中央/茶屋町口改札、3F 九条终端轨道与十条站台带，线路色标、浅栗红主题付费区、选取扶梯/楼梯/直梯，及入闸到京都线的站内路线数据。
- Metro 首版：独立站厅、中间层、共享的 1/2 番线站台，四组改札及选取跨层设施，北改札至 1 番线的路线数据（原路线预览卡已改为站点聚焦导航）。层名不套用 JR 的 B1F/B2F。
- 阪神首版：B1 西口/百货店口，B2 四线终端、独立降车区与东口；跨层设施、半高屏蔽门、南出口电梯与连桥，以及 JR/M16 闸外接驳。采用独立站点与楼层身份，见[阪神布局](./docs/design/stations/hanshin-umeda.md)。
- 东梅田 T20：两座侧式站台，北东／北西／中西／南四组改札，站台及出入口电梯、扶梯、楼梯和 Whity 地下公共连接；见[东梅田布局](./docs/design/stations/higashi-umeda.md)。
- 西梅田 Y11：北端尽头岛式站台，北／中／南改札，保留北口仅出站与中口仅进站；见[西梅田布局](./docs/design/stations/nishi-umeda.md)。
- JR 北新地：B2 岛式站台、B1 东西改札及地面出口；按新增地下图补 DIAMOR、西梅田等公共接驳，见[北新地布局](./docs/design/stations/kitashinchi.md)。
- 各站按地图坐标与地区参考图初步校准相对位置和长轴；JR–阪急连廊及 JR–Metro 下行连接已有空间示意。室内比例与绝对高程仍待核对，尚未开放跨站换乘路线，见[地区整合记录](./docs/development/architecture.md)。
- 周边商业：阪急百货、大丸、LUCUA 两馆、Yodobashi / LINKS、Grand Front 南北馆采用 OSM 简化体块，补充地下入口与 2F 站外联络桥。坡道和小半层按连续步行层归并，不展开商场内部布局，Grand Front 的 Tower A/B/C 以压缩体量在总览显示，选层后隐藏上部造型；见[商业设施连接](./docs/design/buildings/README.md)及[站台比例核对](./docs/design/stations/README.md)。
- 站外短段轨道：JR 东侧两束汇聚后分别向本线、环状线方向延伸；阪急九条站内轨道汇入京都、宝冢、神户三组独立双线，再向十三一侧并行弯曲延伸。曲线为缩短的走向示意，非完整道岔配线，见[轨道延伸记录](./docs/design/railways.md)。

- 地上结构：1F 中央改札与西口、M2F 夹层通道、2F 六组 1–11 番线站台、3F 南北连络桥。
- 梅北地下区域：B1F 地下改札与站厅、B2F 两组 21–24 番线站台及西口连接通道。
- 北高南低的倾斜大屋顶、采光带、简化桁架、地面平行站台与雨棚；梅北地下站台相对地面长轴斜交约 31°（按 OSM 轮廓估算）。
- 楼层聚焦、分层展开、屋顶显隐、缩放、平移、复位。
- 聚焦某层时保留全部下层并灰化，上层隐藏；下层用于参照，地图点选以当前层为主。
- 地理版本默认朝正北，可用鼠标中键围绕拾取点旋转／俯仰；地区 X 向东、Z 向南，指南针随镜头投影。
- 点选闸机、售票处、自动售票机、扶梯、直梯，或用下拉列表定位设施；来源页码保留在数据与文档中。售票机组覆盖中央口、樱桥口、西口、御堂筋口、桥上口和梅北地下口。
- 扶梯带踏步、齿槽、黄色边线、侧板和连续扶手；直梯带半透明井道、轿厢和层门。楼层聚焦时保留完整扶梯和楼梯，已显示直梯保留完整井道、轿厢和两端落台；内部连接裁剪楼板开口，北中庭 2/3 号外缘连接保留开放中庭。
- 樱桥口 51 先到 M2F，再经独立短楼梯前往站台；夹层 17–31 按资料逐项建模。3F 联络桥南端补充 15/16/I，大楼 2F/3F/4F 入口与车站标高分别标注。
- 改札边界设连续围栏，在闸机组处留通行口；闸内外地面颜色继续辅助识别。
- 中央口按 1F 平面图补充两组闸机、售票与咨询区域、东侧店铺、南端 Crost 楼梯/扶梯以及往大丸的小半层台阶。机柜数量、步数与高差均为示意。
- 保留的 JR 测试路线数据包括：中央改札到地面 5/6 番线、西口经闸内连接通道到地下 21/22 番线、北侧 B1F 经站外地下通路到梅北改札后下至站台。到梅北闸口前的第三条路线属于公共通路。演示终点不代表每班 HARUKA 的发车番线。
- 手机布局与双指缩放已编写，尚未在浏览器或真机验证。

## 检查与交付

```sh
npm run typecheck
npm test
npm run build
```

入口为 `dist/index.html`，通过相对路径加载同目录的 `app.js` 与 `styles.css`；当前地图数据随 JS 打包，后续模型、图片等可拆为独立资源。复制或部署时保留整个 `dist/`，无需将所有资源内嵌 HTML。当前无 CDN、远程字体或外部地图请求，保留第三方许可证。主要通过 HTTP 访问，`file://` 打开兼容性仍需浏览器验证。`dist/` 不纳入 Git。

本轮已通过严格类型检查、构建及导航规则测试；未进行浏览器自动操作或视觉验收。后续先人工查看屋顶比例、展开遮挡、移动端可读性和路线显示，再推进精确地图数据。
