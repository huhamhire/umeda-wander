# 阶段二：车站模块与地理校准

2026-11-16 开始。当前完成目录迁移与首批包络对照，未完成七站内部布局校准；H5 仍使用兼容旧坐标。不得将这批目录迁移描述成空间重构已经完成。

## 维护入口

- `src/infrastructure/stations/<station-id>/index.ts`：七站独立入口，登记仍在 `station-maps.ts`。
- JR 的 `layout.ts`、`upper-links.ts`、`south-forecourt.ts`：原有布局、上层连接及南侧前庭。原根目录文件只作兼容转发，避免现有公共区和测试引用失效。
- `src/infrastructure/stations/{jr-osaka,hankyu-umeda,metro-umeda}/calibration.ts`：试点各自的校准依据和待核对项。
- `src/infrastructure/geography/`：地理坐标框架、OSM 快照适配；不包含具体车站的内部设施。
- `src/infrastructure/district/calibration-registry.ts`：试点校准登记，不推断站间寻路连接。
- `src/domain/map/spatial-block.ts`：米制平面坐标、包络语义。x 向东，z 向南；原点与第一阶段一致。

原始快照继续保存在 `data/geography/`。生成图和报告在 `build/geography/`，不提交；不要将 Node 文件读取放进浏览器模型模块。

## 本批对照与发现

运行：

```powershell
node scripts/geography/render-plan.ts
node scripts/geography/render-station-calibration.ts
magick build/geography/station-calibration.svg build/geography/station-calibration.png
```

输出 `station-calibration.svg` 和 `station-calibration.json`。蓝色为 OSM 建筑面，M16 单独标记为近似留位；红虚线为旧场景楼板投回地理基底。保留旧偏移以显示误差，而不是将其偷偷消除。

阪急旧模型向道路东侧超出建筑边界，JR 的站厅及周边地面也存在明显越界。需要分别校准站台端点、站厅与公共接口，不能用建筑包络直接等比压缩全部模型。JR OSM 站房面不是全部站台；梅北必须单独处理。M16 只有规划留位，尚缺平台端点依据，不能把留位宽度当成岛式站台宽度。

本批迁移保留所有站点/设施/楼层 ID 和旧展示行为。公共连廊尚未移动至新坐标，避免新车站与旧通路断开后被误认为可用成果。

## 建筑外壳与高度要求

用户要求保留现有主要建筑风格，但按新区域轮廓重建，并纠正整体偏矮。后续建筑配置放到 `src/infrastructure/buildings/<building-id>/`，共享外壳生成器放到 `src/presentation/models/`。不提前创建空目录。

裙楼、塔楼、外环回廊必须独立。尤其 Yodobashi 内侧圆弧裙楼与外侧 2F 回廊、北侧酒店；Grand Front 南北馆；阪急南侧贴边塔楼；大丸及上部酒店；LUCUA 办公塔楼；阪神与 JP Tower，不能直接把整块建筑基底拉伸到塔楼高度。

旧模型存在明显的高度压缩，例如 Grand Front 三座塔楼仅为 18/20/17 个旧展示单位。新的高度应使用米，与平面框架一致；若需要视觉压缩，必须另列展示倍率，不能修改数据高度。已有快照 `height` 可作为带来源的 OSM 记录（不是独立实测），只有 `building:levels` 时楼层数与估计层高分开记录。无依据的高度明确标作估计，不能伪称已核实。

当前快照含 Yodobashi 149.34 m、阪神 188.9 m、JP Tower 188 m 标签；这些是整个复合体的最高高度，不能赋给全部裙楼。塔楼分部轮廓需要另查快照中的 building:part 或现有缓存记录。建筑最终在总览展示完整外壳，分层仍隐藏外层装饰。

### 阪急南端与轨道避让复核

首轮北移约 20 m 后，站厅虚线外缘仍过近；本轮改为相对原始试拟合累计北移约 40 m（x -8、z -40），保留长宽和设施相对位置。检查对象包含全部楼层楼板，而不只检查平台。以原始 OSM 地面 JR 轨道中心线加示意道床 4.2 m，再向两侧加 3 m 缓冲，自动检查各楼板与缓冲区域不相交。该缓冲用于视觉布局，不是铁路安全净距。

轨道从原始快照独立提取到 `data/geography/railways/`，不覆盖地面数据；校准图显示原有轨道的汇合和弯曲。地下轨道不混入地面图，building_passage 类型高架轨道保留。新增轨道暂为地理参照，站台与单条轨道的精确衔接仍需后续校准。

### 依据与限制

- 梅北使用 data/geography/umeda-osm.xml 的 way 695972638（23/24）与 695972639（21/22）。按既有北向方位角 27.335° 投影，纵向跨度约 211.6 / 218.2 m、中心约 (188.12,581.50) / (204.58,590.33)。本批采用共用直轴、215 m 长度，实际平台弯曲尚未重建。弯曲外包络 21–23 m 的横向跨度不能当岛台宽度；8.2 m 为展示拟合，非实测。
- 其余站端点是既有道路基底、underground/network.ts 留位和地区 PDF 的人工拟合，并非新增测量。北新地参照最终投影的 station-interfaces.ts 区域，不使用旧的 375 m 长留位当站台长度。内部连接关系仍来自各站构内图。
- 梅北本批包含核心 94/95/96/97 扶梯、AD/AE 电梯，以及分开的 B1 闸内外空间。西口 92/93、AB/AC 与 B2 付费通道、LUCUA 北侧 B1 公共绕行，需要分别连接两个独立框架的接口。本批不将旧外部通道直接拉伸过去，不宣称两段已接通。
- 西梅田、北新地新增米制短段双轨，按站台半长计算外延起点，防止旧版固定 85 单位节点落入新站台、造成回折。四桥线只向南延伸，东西线向东西延伸；东西线两轨均在四桥线两轨下方通过。y=-24/-16 暂留展示高度，并非实测工程标高。
- 新站厅轮廓仍为构内图的规则化示意，公共前庭及外部入口需要继续按地下异形空间收边。H5 仍使用旧场景，此批是平面校准，不是完整三维验收。

### 离线检查

运行 node scripts/geography/render-station-interiors.ts 生成道路底图上的七站对照；增加 --underground 参数生成地下公共网络上的车站对照。分别输出 build/geography/station-interiors.svg 和 underground-station-interiors.svg，可转 PNG 检查。第二张不叠加地面 JR 模型。公共网络不因拟合被自动裁剪，也不产生跨站寻路边。

回归覆盖七站唯一身份、旧实例不变、东梅田不混入旧坐标、梅北独立轴、平台设施落点、双轨外延不回折、四个跨线交点的上下关系。下一步优先处理梅北两类连接及各站公共接口收边，再统一标高、开口、设备尺寸和正式 H5 切换。

### 梅北缓弧修正
替换上一批的直轴简化：依据仓库 OSM 两组轮廓的共同弯曲趋势，以 215 m 纵向跨度、12 m 弓高和 -6 m 横向偏移拟合二次缓弧。数值为示意拟合，不是实测。站台边缘、离线轨道、设施落点共用曲线坐标；电梯门向跟随局部切线。曲线端外采用切线延续。正式 H5 尚未迁移，因此本批未更改旧场景的屏蔽门模型；运行时迁移时须使用同一曲线采样。
