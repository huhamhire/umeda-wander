## 维护入口

- JR 的 `layout.ts`、`upper-links.ts`、`south-forecourt.ts`：原有布局、上层连接及南侧前庭。原根目录文件只作兼容转发，避免现有公共区和测试引用失效。

原始快照继续保存在 `data/geography/`。生成图和报告在 `build/geography/`，不提交；不要将 Node 文件读取放进浏览器模型模块。

## 本批对照与发现

运行：

```powershell
node scripts/geography/render-plan.ts
node scripts/geography/render-station-calibration.ts
magick build/geography/station-calibration.svg build/geography/station-calibration.png
```

输出 `station-calibration.svg` 和 `station-calibration.json`。蓝色为 OSM 建筑面，M16 单独标记为近似留位；红虚线为旧场景楼板投回地理基底。保留旧偏移以显示误差，而不是将其偷偷消除。

阪急旧模型向道路东侧超出建筑边界，JR 的站厅及周边地面也存在明显越界。需要分别校准站台端点、站厅与公共接口，不能用建筑包络直接等比压缩全部模型。JR OSM 站房面不是全部站台；梅北必须单独处理。M16 只有规划留位，尚缺平台端点依据，不能把留位宽度当成岛式站台宽度。

本批迁移保留所有站点/设施/楼层 ID 和旧展示行为。公共连廊尚未移动至新坐标，避免新车站与旧通路断开后被误认为可用成果。

## 建筑外壳与高度要求

用户要求保留现有主要建筑风格，但按新区域轮廓重建，并纠正整体偏矮。后续建筑配置放到 `src/infrastructure/buildings/<building-id>/`，共享外壳生成器放到 `src/presentation/models/`。不提前创建空目录。

裙楼、塔楼、外环回廊必须独立。尤其 Yodobashi 内侧圆弧裙楼与外侧 2F 回廊、北侧酒店；Grand Front 南北馆；阪急南侧贴边塔楼；大丸及上部酒店；LUCUA 办公塔楼；阪神与 JP Tower，不能直接把整块建筑基底拉伸到塔楼高度。

旧模型存在明显的高度压缩，例如 Grand Front 三座塔楼仅为 18/20/17 个旧展示单位。新的高度应使用米，与平面框架一致；若需要视觉压缩，必须另列展示倍率，不能修改数据高度。已有快照 `height` 可作为带来源的 OSM 记录（不是独立实测），只有 `building:levels` 时楼层数与估计层高分开记录。无依据的高度明确标作估计，不能伪称已核实。

当前快照含 Yodobashi 149.34 m、阪神 188.9 m、JP Tower 188 m 标签；这些是整个复合体的最高高度，不能赋给全部裙楼。塔楼分部轮廓需要另查快照中的 building:part 或现有缓存记录。建筑最终在总览展示完整外壳，分层仍隐藏外层装饰。

### 阪急南端与轨道避让复核

首轮北移约 20 m 后，站厅虚线外缘仍过近；本轮改为相对原始试拟合累计北移约 40 m（x -8、z -40），保留长宽和设施相对位置。检查对象包含全部楼层楼板，而不只检查平台。以原始 OSM 地面 JR 轨道中心线加示意道床 4.2 m，再向两侧加 3 m 缓冲，自动检查各楼板与缓冲区域不相交。该缓冲用于视觉布局，不是铁路安全净距。

轨道从原始快照独立提取到 `data/geography/railways/`，不覆盖地面数据；校准图显示原有轨道的汇合和弯曲。地下轨道不混入地面图，building_passage 类型高架轨道保留。新增轨道暂为地理参照，站台与单条轨道的精确衔接仍需后续校准。
