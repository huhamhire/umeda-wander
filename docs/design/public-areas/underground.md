# 阶段三：地下公共板块装配

> 设计依据与核对记录。历次检查数量、性能样本和“本轮”状态属于当时快照，不是当前验收结论；当前范围与未决项以 [Roadmap](../../spatial-refactor-roadmap.md) 为准。

更新：2026-11-17。本轮完成地下公共网的首批正式装配；建筑门洞、部分出口与具体标高仍待核对，不将本批称为现场导航验收。

## 本轮结果

- 原 PDF 黄色区域的异形轮廓、凹凸、曲线和街区孔洞继续使用既有道路配准结果；没有重新简化成等宽连桥。
- 公共网分为九个独立维护板块：北中庭、M16 接驳、阪急地下区、Whity、Crost、阪神—西梅田／第一生命、DIAMOR、北新地／曾根地下道、外围延伸。运行时共有 39 个公共面，管理窗口边界不作为物理围墙。
- 所有公共 B1 板块与车站 B1 使用同一 -8 m 展示面和展开序号。16 处 B1 改札的全宽采样均有同高公共面承载，并且都接入同一个地区公共连通分量。跨管理接缝的门组允许引用多个相邻面，不能要求落在同一数组元素中。
- M16 中北西前庭沿 JR 侧接入北侧 B1；中北东前庭沿阪急侧接入地区网；北口西侧增加绕开付费区的衔接面。这三处是依据构内图关系编写的估计接驳面，原 PDF 投影仍独立保留，离线图以虚线标出。
- 西梅田公共带调整到付费站厅东侧，北／中改札朝东接入；付费站厅和站台仍偏西，南改札继续位于南端。既有独立车站接口、设施锚点和开口随本站数据调整。
- 北新地南侧取消未经确认的整条连续公共站厅，只保留具体出口设备的局部落台；不以补地板的方式假定它与北侧通路直接连通。
- 当前 18 个建筑地下占位与公共面、车站内部相减，并去除相互重复。大部分保留 OSM 宿主，E-ma／Hilton West／MARU 使用同一地下图投影的独立街区轮廓（见后文）。按区块区分淡色，名称贴在平面内，窄碎片不强放文字。占位不表示整个建筑地下室可通行。

没有新增跨站寻路边。几何连通检查不是路径、通行条件或无障碍路线认证；JR 中央口仍为 1F，梅北西口 B2 闸内通道与北侧 B1 闸外公共网分开。

## 可重建检查

运行 `node scripts/geography/review-stage-three.ts` 输出：

- `build/geography/stage-three-underground.svg`：核心地区公共网、道路、建筑占位、付费区及接口。
- `stage-three-north.svg`、`stage-three-south.svg`：局部放大，红虚线显示人工接驳范围，蓝色表示本轮公共设备。
- `stage-three-audit.json`：板块、16 个接口绑定、道路控制点投影、公共设备、建筑接触状态。分区只改变管理所有权，自动验证分割前后公共面的并集相同、无重复面、孔洞保留。

公共网并集当前有六个平面连通分量：主地区网及五处独立出口／短升降落台。16 个改札均属于主分量；未用不明路线把独立落台强接进去。报告中的 `component=-1` 表示某个控制点不在当前公共面内，可能位于车站占用、建筑或待确认区域，不能自动视为该点应该补通。

类型检查、223 项测试及构建通过。公共设备上层真孔洞、竖直电梯井、全图设施稳定编号和付费边界均有回归。已查看带道路叠加的北／南局部 PNG；没有操作浏览器，WebGL、文字遮挡、手机触控和设备聚焦动画仍待人工复核。

同条件 Node v24.18.0 / Windows 离线 CPU 几何构造约 612–633 ms、12,139 Mesh、925,576 三角形；阶段二约 680 ms、11,875 Mesh、约 906,000 三角形。耗时仅为两次离线样本，不能据此认定性能改善；不含文字、GPU 上传及浏览器交互。`profile-scene.ts --output=stage-three-profile.json` 可复测。

## 2026-11-17 地下街区占位修订

本批没有修改黄色公共开挖几何、道路锚点或车站位置。E-ma／Hilton West 原先用地上 OSM 实体作为 B1 占位，和地下地区图中的街区边界存在差异；改为提取同份 PDF 的绿色街区面（绘图对象 405／436）。MARU 使用对象 243 的闭合弧形外边界，不以内部装饰线或矩形替代。

原始边界在 `data/geography/underground/basement-source.json`，保留源 PDF SHA-256、页码、绘图对象序号、边界类型及曲线采样。`basement-outlines.json` 经 `sourceProjection().projectRing` 与公共网共用道路校准；E-ma／Hilton West 的地上 OSM 数据与白模不变。原图绿色面和闭合线只能支持占位示意，不能证明实际地下租赁范围或具体入口。

现役适配在 `public-areas/south-diamor/basement-outlines.ts`，总清单仍由 `basement-buildings.ts` 登记。新增 MARU 后共 18 个宿主；填色、平面名称、公共面／付费区避让继续使用共享占位算法。E-ma／Hilton West／MARU 均有几何接触，地下仍是原来的 39 个公共面、6 个平面分量、16 个 B1 改札接口。

核查报告增加 `basementGaps`，计算真实内／外边界间距，包括公共面的建筑孔洞。JP Tower 当前最小间距约 **10.635 m**，位于其东南角与阪神—西梅田公共面的西端；这是图上几何诊断，不是实测距离或建议线路。`stage-three-basement-review.svg` 的短虚线只表示诊断差距，不渲染到 H5。

第一酒店暂不补独立占位：源图对象 63 将酒店附近道路、建筑细部与站前第 1 大楼组合描绘，不能把整条复合线封闭成酒店。北新地南侧出口和西梅田短落台的接入／高差仍按原清单待核对，本批未用新的通廊强接。

重建顺序（修改道路校准后也需重投影占位）：

```powershell
$env:PYTHONPATH='build/pdf-tools'
python scripts/geography/extract-basement-outlines.py
node scripts/geography/build-basement-outlines.ts
node scripts/geography/build-ground-context.ts
node scripts/geography/review-stage-three.ts
```

新旧 PDF 提取共用 `pdf_vectors.py`，旧黄色源轮廓重新提取后逐字节一致。离线南侧占位图已检查；真实 WebGL、手机交互与门洞现场条件尚未验证。

本批类型检查、250 项测试、构建和差异检查通过。新增回归覆盖源哈希、共用投影、MARU 曲线、邻接区块颜色区分、占位避让、地面完整遮盖及孔洞边界距离；没有新增地下通行路线。离线 CPU 几何构造可用 `profile-scene.ts --output=roadmap-detail-profile.json` 复核，不代表浏览器帧率或首屏耗时。
