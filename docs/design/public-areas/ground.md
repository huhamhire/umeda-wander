# 地面展示范围与道路连续性

原始 OSM 快照、完整地面投影和地下公共面保持不变。运行时地面使用 `data/geography/display-context.json`，由构建脚本独立生成；不把渲染筛选伪装成修改了原始地图。

## 范围与对象

- 以已建立的地下网络外围、七站站体／站台、核心商业体及二层连廊构造展示范围，外围留 35 m 道路参照。只简化展示遮盖层，不简化地下凹凸轮廓或站模。
- 普通建筑轮廓绘在地面，只保留地下宿主、已建模商业和连廊目的地。Inogate 与 Grand Green 南馆 Gate Tower 使用地面轮廓标明目标。对应的 2F 只显示公共连桥和落台。
- 已知建筑在图上相邻或属于保留清单，不表示地下门位已验证。JP Tower、E-ma、Hilton West 的入口仍按 roadmap 单独核对。

## 道路保持连接

1. 同一 OSM way 保留第一次进入范围到最后一次离开范围之间的原始折线，中间即使暂时走出初始遮盖范围也补齐，避免断成碎片；只裁外围端头。
2. 不同 way 使用同名／同 ref 和原始共用顶点识别道路接续。沿原始道路图保留连接已选路段所需的中段，不把交叉但无共用顶点的线强行连接。
3. 未命名 way 只保证自身中段连续，不在复杂路口猜测跨 way 的对应关系。原始快照缺失的路段、立交或没有数据节点的断点不能凭空补直线。
4. 地面遮盖随保留的道路中段扩展，避免道路下方出现无底的裂缝。地下入口对遮盖层、保留的道路铺装和建筑占位同步裁孔。

`context-audit.json` 记录涉及中段保留和相邻分段接续的 OSM ID；道路图用于展示连续性。

## 维护与复核

```powershell
node scripts/geography/build-ground-context.ts
node scripts/geography/review-ground-context.ts
```

- `context-policy.json` 维护边缘余量、显示轮廓简化容差和明确补充的宿主 ID；已登记地下宿主和 2F 目的地随清单更新。
- `scripts/geography/road-continuity.ts` 保持道路源折线和分段连接，`context-scope.ts` 只生成外围遮盖；为避免细分建筑边界导致扫描线退化，分批两两合并。裁剪运算交点做毫米级数值归一化，不表示测量精度。
- 输出离线图 `build/geography/display-context.svg`、`context-audit.json`；原始 references 不改写，生成预览不提交。
- 修改底层地面、站体、地下网或高架板块后重建展示资源。裁剪后的几何受混合来源约束，不取代版权弹窗中的纯 OSM 数据下载。

自动检查覆盖地下面、站台、核心建筑及连廊不被裁掉，道路片段连续、无关分支剔除，以及遮盖／铺装不重新封闭入口。浏览器与手机的验收条目见 [Roadmap](../../roadmap.md)。
