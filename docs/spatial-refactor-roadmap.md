## 目标与基本原则

1. 地面道路、建筑轮廓和车站包络使用共同的空间基准，整体保持接近真实的比例、方位与间距，不要求测绘级精度。
2. 每座车站是独立板块，可以拥有独立目录、内部子区域和维护说明。公共区域可以拆为一个或多个独立板块，容纳地下公共网络、地面公共空间及 2F 连接。
3. 商业建筑独立维护轮廓、公共入口和必要公共通廊，不展开无关店铺内部。
4. 设施的造型尺寸允许适度放大、简化；放大不能移动真实连接关系、改变付费边界或造成穿模。建筑和站台整体不能为了容纳设备而任意放大。
5. 物理空间、连接关系、探索楼层、显示变换分开。分层展开、建筑压缩高度和设备夸张不能反向修改平面基准。
6. 1F 地面路网独立控制显隐，不与 1F 站厅或建筑轮廓开关绑定。关闭地面路网不删除连接数据，也不隐藏车站入口。
7. 公共组件、设备模型和通用算法集中复用；各板块不复制渲染器，不通过导入其他板块内部文件获取端点。
8. 继续采用 TypeScript、Three.js、esbuild、单 HTML 入口及独立资源。此次重构不以替换技术栈或上线正式寻路为前提。

## 板块边界与共享能力

### 板块分工

| 板块 | 自己维护的内容 | 对外提供 |
| --- | --- | --- |
| 单个车站 | 本站站厅、付费区、站台、设施、本站轨道及内部连接 | 外围分层轮廓、公共接口、设施、来源与校准信息 |
| 商业综合体 | 裙楼/塔楼轮廓、外部入口、必要公共大厅和回廊 | 分层建筑边界、公共接口、遮挡体 |
| 地面公共区域 | 道路范围、人行空间、广场、过街位置 | 地面几何、公共接口、独立显示组 |
| 地下公共区域 | 地下街异形空间、节点、建筑占位孔洞、附属设施 | 分层公共面、接口和连接骨架 |
| 高架公共区域 | 2F 天桥、分支、落台和公共垂直连接 | 桥面、接口、落台和开口需求 |

公共板块按有明确边界的区域或可独立核对的连接系统拆分，例如北侧中庭公共区、南侧 DIAMOR 区、Whity 区。允许一个公共板块覆盖多个层级；不要为了目录整齐把同一连续节点拆成互相依赖的小块。板块是维护边界，不是完整 DDD 限界上下文或独立应用，每站无需复制一套领域类型与服务。

同一公共空间只能有一个几何所有者。重叠区域通过约定裁剪或共享接缝衔接，不能由两个板块各画一次。公共设施归实际承载的公共板块，即使借用某站相邻层标高，也不能误归为本站付费设施。

### 目录方案

沿用根级 DDD 分层，在基础设施内按板块组织数据；只有存在站点专属规则时，才增加相应应用层或呈现层目录，不为每站生成空壳架构。

```text
src/
  domain/map/                  # 坐标、板块、接口、楼层、设施与通行语义
  application/                 # 组装、校准应用、开口规划和可见性协调
  infrastructure/
    geography/                 # 地图快照适配、来源记录、投影及校准配置
    stations/
      jr-osaka/                # index、layout、facilities、portals、rails 等按需拆分
      hankyu-umeda/
      ...                      # 其余五站各自独立目录
    buildings/                 # 各商业综合体独立目录
    public-areas/
      ground-core/
      north-atrium/
      south-diamor/
      whity/
      north-decks/
      south-decks/
    district/                  # 板块登记、接口绑定及总图入口
  presentation/
    components/                # 公共 UI，例如面板控件、模态框
    models/                    # 公共楼板、扶梯、直梯、轨道、建筑造型
  utils/                       # 无地图领域语义的通用工具
tests/                         # 按站点、公共区和共享能力分组
docs/                          # 总索引、板块说明与校准记录
```

这是目标组织方式，不要求在第一阶段集中搬移所有文件。`StationMap` 等现有接口通过适配保持可用；目录迁移和空间调整分开提交，减少审查噪声。若测试改为子目录，需同步调整当前只匹配 `tests/*.test.ts` 的测试命令，确保测试不会被漏跑。

共享能力按语义放置，不把所有文件集中进 `utils`：空间拓扑/坐标规则属于领域层，接口解析/开口规划属于应用层，数据读取属于基础设施，Three.js 设备模型和 DOM 组件属于呈现层。共享层不能导入某个车站或商场的具体布局。局部维护只需读取板块说明、公开接口和相关公共能力，不必读全图数据。

### 板块接口约定

以下为后续接口完善与装配要求：

- 板块：稳定 ID、类型、局部坐标框架、地理定位/校准、分层包络、实体清单、公共接口及来源记录。
- 接口：稳定 ID、所属板块、位置或边界线段、方向、接入宽度、实际楼层/标高、探索层分组、公共/付费属性及依据。
- 跨板块连接：引用两端接口 ID，几何只由所属公共板块维护；组装时统一转换坐标并校验，不引用对方内部设施数组下标。
- 外部接口向内引用本站布局；地区绑定向外引用接口。站点不得反向导入总图或另一站的完整数据，避免循环依赖。
- 接口未核实时记录为待确认，不以最近点吸附、最短直线或同层重叠自动认定互通。
- 装配阶段检查缺失引用、重复实体、接缝位置/宽度、标高及通行属性。平面交叉与楼层同组均不表示连接。

## 空间与数据规则

### 坐标与比例

- 以地区固定原点建立局部米制平面，记录经纬度投影方式和轴向约定。保留固定斜视的画面方向，不能混淆地理北向与相机朝向。
- 地图建筑/道路直接投影；车站保留局部坐标，通过单一校准变换进入地区坐标。优先平移、旋转与统一缩放；确需轴向分别校准时记录原图畸变和依据，不作为避让补丁。
- 一个板块的站体、设施锚点、边界、轨道端点和公共接口共用变换，不能分别加显示偏移。
- 站点 POI 中心不是地下站台端点或建筑包络。站体须综合轨道走向、入口和构内图定位，不能仅按站名坐标放置矩形。
- 保存实际/估计标高及其可信度；探索层继续允许小半层归组。地下线路相交保留上下关系，标高未知时不能编造测量净空。
- 设施显示尺寸与空间锚点分开。设备放大时同步规划模型、井道、楼板开口、围栏和落台；必要时采用简化符号，不能把通道堵死或把扶梯拉跨站。

### 来源与校准记录

优先使用可复用且来源清晰的公开矢量地图作为道路与建筑基底。卫星图可作方位和外形核对；只有确认允许对应用途时才提取几何，不因公开可见就推定可描摹或分发。暂不将卫星影像作为运行时背景的必选项。

每份数据记录发布方、原链接、获取/版本日期、原始范围与坐标系、许可、处理步骤及派生文件。更新 `source-credits.ts` 和来源审计，保留适用的 OSM 署名与派生数据交付要求。授权待确认的候选不默认纳入可发布资源。

每个板块保留校准表：外部包络尺寸、主轴、至少覆盖两轴的可靠锚点、拟合方法、残差及未确定部位。条件允许时采用三个以上非共线锚点；无法达到时明确降低可信度，不从示意图推导虚假的精度。把直接事实、人工推断、视觉简化分开记录。

## 实施顺序、检查与交付

阶段基准依赖为“一 → 二 → 三 → 四”。本轮按用户指示进入阶段四；阶段三的独立待核对项继续记录，不阻塞已有资料支持的二层装配。允许先在试点区贯通四阶段验证接口设计，但不能以局部试点代替七站迁移验收。资料不足的连接只记录，不阻止有依据的其他区域推进。

每个实施批次包含：修改范围、来源与拟合依据、板块入口、可检查的前后平面图、未确定项、运行检查结果。建议将目录移动、坐标框架、单站迁移、公共区重建分别作为可审查变更；未经用户要求不自行提交。

- 数据检查：投影往返/已知方向、校准变换、稳定 ID、重复所有权、接口引用及接缝、孔洞、公共/付费边界和轨道上下关系。
- 交互检查：总览与各层、0%/中间值/100% 展开、建筑轮廓与路网独立显隐、区域灰化、设施聚焦/筛选及完整跨层模型。
- 视图检查：离线平面图和固定斜视图优先；桌面与窄屏尺寸检查可见范围、文字、遮挡、面板和控件。遵循“不直接操作浏览器”的约定，工具无法验证的项目明确列为待人工检查，不以构建成功代替视觉验收。
- 工程检查：按改动运行 `npm.cmd run typecheck`、`npm.cmd test`、`npm.cmd run build` 及 `git diff --check`。纯文档整理无需运行应用测试。
- 性能检查：记录重构前后相同设备/视图的初始化耗时、几何量和交互表现；静态道路几何可合批，过密设备细节按缩放简化，不提前承诺未经测量的帧率。

本轮不包括实时定位、正式跨站寻路、通行时间估算、商场店铺细节、实时施工状态及在线地图编辑器。连接骨架为未来导航保留语义，不自动升级成可用现场导航。
