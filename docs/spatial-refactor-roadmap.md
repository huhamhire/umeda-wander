# 梅田地图空间重构 Roadmap

状态：阶段一已开始，已生成 OSM 建筑与道路首版平面校对图，尚未验收；现有 H5 场景尚未迁移。更新日期：2026-11-16。

按本文四个阶段推进；每阶段产出可检查的地图与校准记录，通过验收后再扩大范围。当前 H5 及既有布局文档仍描述旧版示意数据，不能视为已完成本计划。阶段一重建方式及限制见 [地理数据说明](../data/geography/README.md)，输出为 `build/geography/ground-plan.svg`。

## 目标与基本原则

1. 地面道路、建筑轮廓和车站包络使用共同的空间基准，整体保持接近真实的比例、方位与间距，不要求测绘级精度。
2. 每座车站是独立板块，可以拥有独立目录、内部子区域和维护说明。公共区域可以拆为一个或多个独立板块，容纳地下公共网络、地面公共空间及 2F 连接。
3. 商业建筑独立维护轮廓、公共入口和必要公共通廊，不展开无关店铺内部。
4. 设施的造型尺寸允许适度放大、简化；放大不能移动真实连接关系、改变付费边界或造成穿模。建筑和站台整体不能为了容纳设备而任意放大。
5. 物理空间、连接关系、探索楼层、显示变换分开。分层展开、建筑压缩高度和设备夸张不能反向修改平面基准。
6. 1F 地面路网独立控制显隐，不与 1F 站厅或建筑轮廓开关绑定。关闭地面路网不删除连接数据，也不隐藏车站入口。
7. 公共组件、设备模型和通用算法集中复用；各板块不复制渲染器，不通过导入其他板块内部文件获取端点。
8. 继续采用 TypeScript、Three.js、esbuild、单 HTML 入口及独立资源。此次重构不以替换技术栈或上线正式寻路为前提。

## 现状与迁移约束

- `station-maps.ts` 已登记七站，`compose-station-maps.ts` 已负责纯组装，保留这些职责和稳定实体 ID。
- `district-placement.ts` 同时含地理锚点、展示偏移、轴向/横向缩放和参考图裁剪投影。必须拆清其用途，逐站替换，不能将已有场景单位直接改名为米。
- `district-map-parts.ts` 聚合商业空间和公共连接；后续拆为公共板块清单及建筑板块清单，不能继续无限扩充一个总文件。
- `south-walkway-plan.ts`、`southern-underground.ts` 已有面状地下空间和孔洞能力，可复用几何处理；其参考图坐标与本站拟合仍需重新校准。
- 楼层、设施目录、编号、开口、围栏、轨道生成、聚焦灰化和镜头取景均存在坐标依赖。迁移时同步检查，不能只替换主体轮廓。
- 原始 `references/` 不覆盖；转换图、校准结果和原始地图快照分开保存，不依赖临时 `build/` 图作为唯一来源。

本计划取代未来迁移区域“车站整体重点放大、通道任意压缩”的设计原则；未迁移区域保留原行为并明确标记。施工临时关闭仍按既有约定忽略。

## 板块边界与共享能力

### 板块分工

| 板块 | 自己维护的内容 | 对外提供 |
| --- | --- | --- |
| 单个车站 | 本站站厅、付费区、站台、设施、本站轨道及内部连接 | 外围分层轮廓、公共接口、设施、来源与校准信息 |
| 商业综合体 | 裙楼/塔楼轮廓、外部入口、必要公共大厅和回廊 | 分层建筑边界、公共接口、遮挡体 |
| 地面公共区域 | 道路范围、人行空间、广场、过街位置 | 地面几何、公共接口、独立显示组 |
| 地下公共区域 | 地下街异形空间、节点、建筑占位孔洞、附属设施 | 分层公共面、接口和连接骨架 |
| 高架公共区域 | 2F 天桥、分支、落台和公共垂直连接 | 桥面、接口、落台和开口需求 |

公共板块按有明确边界的区域或可独立核对的连接系统拆分，例如北侧中庭公共区、南侧 DIAMOR 区、Whity 区。允许一个公共板块覆盖多个层级；不要为了目录整齐把同一连续节点拆成互相依赖的小块。板块是维护边界，不是完整 DDD 限界上下文或独立应用，每站无需复制一套领域类型与服务。

同一公共空间只能有一个几何所有者。重叠区域通过约定裁剪或共享接缝衔接，不能由两个板块各画一次。公共设施归实际承载的公共板块，即使借用某站相邻层标高，也不能误归为本站付费设施。

### 目录方案

沿用根级 DDD 分层，在基础设施内按板块组织数据；只有存在站点专属规则时，才增加相应应用层或呈现层目录，不为每站生成空壳架构。

```text
src/
  domain/map/                  # 坐标、板块、接口、楼层、设施与通行语义
  application/                 # 组装、校准应用、开口规划和可见性协调
  infrastructure/
    geography/                 # 地图快照适配、来源记录、投影及校准配置
    stations/
      jr-osaka/                # index、layout、facilities、portals、rails 等按需拆分
      hankyu-umeda/
      ...                      # 其余五站各自独立目录
    buildings/                 # 各商业综合体独立目录
    public-areas/
      ground-core/
      north-atrium/
      south-diamor/
      whity/
      north-decks/
      south-decks/
    district/                  # 板块登记、接口绑定及总图入口
  presentation/
    components/                # 公共 UI，例如面板控件、模态框
    models/                    # 公共楼板、扶梯、直梯、轨道、建筑造型
  utils/                       # 无地图领域语义的通用工具
tests/                         # 按站点、公共区和共享能力分组
docs/                          # 总索引、板块说明与校准记录
```

这是目标组织方式，不要求在第一阶段集中搬移所有文件。`StationMap` 等现有接口通过适配保持可用；目录迁移和空间调整分开提交，减少审查噪声。若测试改为子目录，需同步调整当前只匹配 `tests/*.test.ts` 的测试命令，确保测试不会被漏跑。

共享能力按语义放置，不把所有文件集中进 `utils`：空间拓扑/坐标规则属于领域层，接口解析/开口规划属于应用层，数据读取属于基础设施，Three.js 设备模型和 DOM 组件属于呈现层。共享层不能导入某个车站或商场的具体布局。局部维护只需读取板块说明、公开接口和相关公共能力，不必读全图数据。

### 板块接口约定

以下为后续类型设计要求，本轮不直接新增实现类型：

- 板块：稳定 ID、类型、局部坐标框架、地理定位/校准、分层包络、实体清单、公共接口及来源记录。
- 接口：稳定 ID、所属板块、位置或边界线段、方向、接入宽度、实际楼层/标高、探索层分组、公共/付费属性及依据。
- 跨板块连接：引用两端接口 ID，几何只由所属公共板块维护；组装时统一转换坐标并校验，不引用对方内部设施数组下标。
- 外部接口向内引用本站布局；地区绑定向外引用接口。站点不得反向导入总图或另一站的完整数据，避免循环依赖。
- 接口未核实时记录为待确认，不以最近点吸附、最短直线或同层重叠自动认定互通。
- 装配阶段检查缺失引用、重复实体、接缝位置/宽度、标高及通行属性。平面交叉与楼层同组均不表示连接。

## 空间与数据规则

### 坐标与比例

- 以地区固定原点建立局部米制平面，记录经纬度投影方式和轴向约定。保留固定斜视的画面方向，不能混淆地理北向与相机朝向。
- 地图建筑/道路直接投影；车站保留局部坐标，通过单一校准变换进入地区坐标。优先平移、旋转与统一缩放；确需轴向分别校准时记录原图畸变和依据，不作为避让补丁。
- 一个板块的站体、设施锚点、边界、轨道端点和公共接口共用变换，不能分别加显示偏移。
- 站点 POI 中心不是地下站台端点或建筑包络。站体须综合轨道走向、入口和构内图定位，不能仅按站名坐标放置矩形。
- 保存实际/估计标高及其可信度；探索层继续允许小半层归组。地下线路相交保留上下关系，标高未知时不能编造测量净空。
- 设施显示尺寸与空间锚点分开。设备放大时同步规划模型、井道、楼板开口、围栏和落台；必要时采用简化符号，不能把通道堵死或把扶梯拉跨站。

### 来源与校准记录

优先使用可复用且来源清晰的公开矢量地图作为道路与建筑基底。卫星图可作方位和外形核对；只有确认允许对应用途时才提取几何，不因公开可见就推定可描摹或分发。暂不将卫星影像作为运行时背景的必选项。

每份数据记录发布方、原链接、获取/版本日期、原始范围与坐标系、许可、处理步骤及派生文件。更新 `source-credits.ts` 和来源审计，保留适用的 OSM 署名与派生数据交付要求。授权待确认的候选不默认纳入可发布资源。

每个板块保留校准表：外部包络尺寸、主轴、至少覆盖两轴的可靠锚点、拟合方法、残差及未确定部位。条件允许时采用三个以上非共线锚点；无法达到时明确降低可信度，不从示意图推导虚假的精度。把直接事实、人工推断、视觉简化分开记录。

## 阶段一：地面基底与独立板块骨架

目标：交付建筑和道路平面布局图，作为本阶段验收对象与后续空间定位基准。本阶段不要求完成车站内部模型迁移或三维交互接入。

1. 盘点现有轮廓、地理点、参考材料和许可，确定覆盖七站、主要商业体及南侧地下街的工作范围；范围边界记录成数据。
2. 建立统一投影与可重复的数据转换流程，保留原始快照、处理结果和来源索引。运行时加载静态资源，不依赖在线地图请求。
3. 绘制主要道路边界或宽度范围、街区、广场及已知步行空间。机动车道路和可步行区域分开，路口不自动生成过街路径。
4. 标记 JR、阪急百货/Grand Building、阪神百货、大丸、LUCUA、Yodobashi、Grand Front、JP Tower 及南侧相关建筑轮廓；区分同一综合体的裙楼与塔楼部件。
5. 按站点、建筑和公共区域整理平面数据归属与来源摘要，记录后续板块登记、坐标和接口契约的需求；不要求在此阶段搬移现有站点代码。
6. 输出统一范围的俯视平面图，附北向、比例尺、建筑名称/索引及来源说明。建筑与道路可分别检查，能与来源地图对照相对位置。

产出：建筑和道路平面布局图、对应可复用几何数据、建筑轮廓清单、坐标说明、来源清单和待确认项。

验收：以平面布局图对照来源地图，核对主要建筑外轮廓、道路走向、路口、街区关系、方位、比例和建筑间距，尤其检查 Grand Front—Yodobashi、JR—阪急及南侧站区关系。比例尺与坐标换算一致，来源及不确定部位可追溯。独立路网开关、移动端交互、三维表现和站内设施调整不作为本阶段验收条件。

## 阶段二：车站包络与内部布局校准

目标：七站在共同地面基底中具有合理的长度、宽度、位置及轨道关系。

1. 先做 JR 东侧—M16—阪急站及阪急百货周边试点，验证站体、道路、轨道及入口约束能同时成立。
   接入阶段一平面基底时，建立板块登记与公共接口契约，并实现独立“地面路网”开关（默认显示）。开关仅控制地面道路背景与附属制图要素，B1/B2 剖切时隐藏，不影响车站楼板、入口、地下及 2F 连接；检查切层与展开不导致地面水平漂移。
2. 对每站制定包络与入口校准表，区分地上建筑、地下站厅、站台和轨道范围；不能要求不同层完全套在同一矩形中。
3. 先校准主轴与站台端点，再调整站厅和付费边界，最后安置内部设备及公共接口；避免将旧场景整体缩小后就视为完成。
4. 为扶梯、直梯、楼梯设统一的显示尺寸策略，保留设备 ID、参考编号及菜单候选；模型比例和孔洞共同调整。
5. 依次完成 JR/梅北、M16、阪急、阪神及南侧 Y11/北新地/T20。南侧三站作为一组复核相对关系，北新地与四桥线单独检查交叉高差。
6. 同步更新轨道延伸与并线，不沿用为旧布局避让制造的 S 弯。暂未迁移的站点通过明确的兼容适配存在，试点旧连接不当作新布局验收依据。

产出：七站独立板块目录、包络/锚点记录、设备显示规则及迁移对照图。

验收：每站可独立组装预览；跨站无非法内部引用；站台和设施落点合理；模型不穿楼板；闸机围栏留口正确；轨道连接连续。跨高差交叉按标高检查，不能用二维相交一律判错。测试容差在试点校准后按数据可信度制定，不先指定无依据的米级精度。

## 阶段三：地下公共区域网络与附属设施

目标：按共同投影重建连续地下公共空间，再对齐站体和建筑接入口。

1. 将地下资料与地面锚点关联，分区校准。参考图仅用于连接拓扑时，不把其排版距离直接作为地理距离。
2. 分板块建立梅北—北中庭—LUCUA、M16 接驳、Whity、阪神—西梅田弧形互通、DIAMOR、曾根地下道与北新地等公共区域。
3. 先核对关键节点、分支顺序、环绕街区及连接层级，再绘制异形公共面；不采用等宽天桥线段强接所有入口。
4. 把建筑占位放入公共网络围合的对应街区，作为占用区/孔洞处理，避免建筑填充盖住通路；同一建筑各层关系保持一致。
5. 将公共区接口与已校准的车站接口绑定；不能穿越付费区补捷径，不因两个边界靠近而增加跨站寻路边。
6. 补齐有资料支持的公共楼梯、扶梯、直梯、入口及方向关系；保留小半层和无障碍连接的区别，缺失信息进入待核对清单。

产出：可独立维护的地下公共板块、接口绑定表、参考拓扑对照图与待确认清单。

验收：关键连接顺序与资料一致；公共面连续、保留建筑孔洞和付费边界；接缝无重复楼板/裂缝；地下无高架栏杆；入口与通路不恢复密集浮动标签。附属设施在涉及层级可见，开口和取景一致。

## 阶段四：2F 连廊与整体验收

目标：依据校准后的建筑位置，重建地上步行连接及上下落点。

1. 核对北中庭—Grand Front/Yodobashi/阪急、LUCUA—梅北上方公共落台、Grand Front 南北馆、JR 南侧—大丸—阪急百货/阪神、JP Tower 等连接。
2. 先确定建筑墙面/回廊接入口、道路跨越位置和分支节点，再生成桥面；不自动按两建筑最近点连接。
3. 保留 Yodobashi 外环回廊、Grand Front 南北馆直连、南侧外围直线走向和弧形楼板退避等明确特征。
4. 补齐 1F↔2F、2F↔建筑上层的公共垂直连接、落台和开口；坡道可归同一探索层，实际连接标高仍有记录。
5. 同步检查建筑外壳、围墙和桥栏杆避让接口。桥栏杆沿用较细、较淡、较密的风格，不能堵住分支。
6. 清理已替换的展示偏移、临时接口适配和重复公共楼板，归档旧坐标说明，更新各板块维护索引。

产出：公共 2F 板块、完整板块装配、来源与校准文档、总览/分层对照图。

验收：连廊走向、分支和落点符合资料；分层不丢失跨层设备；建筑轮廓与路网开关独立；区域聚焦灰化、遮挡标签、设施筛选及移动端居中仍正确。总览中建筑相对关系自然，局部聚焦可辨识设备。

## 实施顺序、检查与交付

阶段依赖为“一 → 二 → 三 → 四”。允许先在试点区贯通四阶段验证接口设计，但不能以局部试点代替七站迁移验收。资料不足的连接只记录，不阻止有依据的其他区域推进。

每个实施批次包含：修改范围、来源与拟合依据、板块入口、可检查的前后平面图、未确定项、运行检查结果。建议将目录移动、坐标框架、单站迁移、公共区重建分别作为可审查变更；未经用户要求不自行提交。

- 数据检查：投影往返/已知方向、校准变换、稳定 ID、重复所有权、接口引用及接缝、孔洞、公共/付费边界和轨道上下关系。
- 交互检查：总览与各层、0%/中间值/100% 展开、建筑轮廓与路网独立显隐、区域灰化、设施聚焦/筛选及完整跨层模型。
- 视图检查：离线平面图和固定斜视图优先；桌面与窄屏尺寸检查可见范围、文字、遮挡、面板和控件。遵循“不直接操作浏览器”的约定，工具无法验证的项目明确列为待人工检查，不以构建成功代替视觉验收。
- 工程检查：按改动运行 `npm.cmd run typecheck`、`npm.cmd test`、`npm.cmd run build` 及 `git diff --check`。本轮仅文档变更，无需运行应用测试。
- 性能检查：记录重构前后相同设备/视图的初始化耗时、几何量和交互表现；静态道路几何可合批，过密设备细节按缩放简化，不提前承诺未经测量的帧率。

本轮不包括实时定位、正式跨站寻路、通行时间估算、商场店铺细节、实时施工状态及在线地图编辑器。连接骨架为未来导航保留语义，不自动升级成可用现场导航。
