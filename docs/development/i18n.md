# 国际化文案维护

页面支持简体中文（`zh-CN`）、日本語（`ja`）和 English（`en`）。右上角选择语言后，`umeda-language` Cookie 保存一年。首次访问按浏览器语言列表的优先顺序匹配主语言码，均无法匹配时使用简体中文。浏览器拒绝写入 Cookie 时，当前网址用 `lang` 参数保留手动选择。

## 领域与目录

```text
src/
├── domain/i18n/message.ts                  # Locale 与参数契约
├── application/i18n/format-message.ts     # 无 DOM 的具名参数替换
└── infrastructure/i18n/
    ├── index.ts                           # 具类型的 messageText / resolveMessage
    ├── en/                                # 英文，同一套领域与键集
    ├── ja/                                # 日文，同一套领域与键集
    └── zh-CN/
        ├── index.ts                       # 中文领域登记
        ├── ui.json                        # 界面、辅助标签和通用方位
        ├── stations.json                  # 七站楼层、改札、设备及区域名称
        ├── buildings.json                 # 建筑和体量的显示名称
        ├── public-areas.json               # 地下及 2F 公共区域
        ├── facilities.json                # 通用设施类型和组合名称
        └── railways.json                  # 线路和行车方向
```

文件按少量领域划分，不再按每座建筑或每个板块切碎。key 内继续保留车站、建筑和实体的子层级，避免同一领域出现含义不明的编号。

版权正文按语言独立维护在 `src/content/source-credits.<locale>.html`，构建时整份嵌入原生弹窗。弹窗入口、标题与关闭按钮的无障碍名称仍归 `ui.json`。机器可读地理数据的编制元信息在 `data/geography/osm-export-metadata.json`。

## key 与参数

key 使用稳定语义，例如 `stations.hankyuUmeda.facilities.gate3f.name`、`ui.facilities.empty`。不以中文、日文、英文整句作为 key，也不通过显示名称反查领域身份。重命名显示文案不得改变设施 ID、内部编号、资料 URL、图层 ID 或几何归属。

```typescript
messageText('facilities.labels.trackNumber', { number: 21 });
messageText('ui.errors.initializationDetail', { message: errorMessage });
```

组合语句保留完整模板，以 `{number}`、`{location}`、`{kind}` 等具名参数插入数据，不按中文语序拼接可翻译词片段。缺少参数或未知 key 会明确报错，避免页面静默显示 key。`messageText` 本身返回纯文本；DOM 使用 `textContent`，HTML 模板由构建脚本负责转义。

页面模板以 `{{ui.heading.title}}` 等 key 维护，由 `scripts/html.ts` 构建为单一入口。中文提供静态回退，日语和英语以 HTML 模板随入口交付。启动时应用匹配的模板、页面标题和 `lang`。地图标签和楼板文字在场景初始化时使用同一语言，语言切换重新加载页面。短期会话快照用于恢复楼层、设施筛选、显隐设置和镜头，恢复后即清除。

纯应用服务只输出语义标识；地区基础设施在组装边界解析公共面／连廊名称，不让领域层依赖 DOM、中文词库或渲染器。

## 不属于翻译词条的内容

- 门面装饰文字属于建筑模型常量，例如 `buildings/daimaru/signage.ts` 中的“大阪駅 / OSAKA STATION”，不随界面语言变化。
- 资料原文件名、外部 URL、OSM 原始标签及用于源数据匹配的日文名称保持原样。
- `Evidence.detail`、校准说明、开发错误和控制台诊断暂按技术／事实资料维护，不当成界面文案批量翻译。
- `data/geography/` 的源图与原始资料名称不被本次迁移改写；未来需要面向用户多语言显示时通过稳定实体 ID 增加显示词条，不修改事实源。

图上标签是否显示、换行或属于哪个区域，必须由实体身份和展示规则决定。原来依赖中文通路名称的隐藏规则已改用稳定区域 ID；站前大楼的楼板文字也按建筑 ID 选择排版模板。

## 校验

新增词条时同步填写三种语言，具名参数保持一致。`tests/presentation/i18n.test.ts` 校验键集、参数、语言匹配顺序、构建后的页面片段与版权资源。界面改动需复核移动端的英文长词、日文换行和字号。

JP 大楼的业主正式名称为 `JPタワー大阪 / JP TOWER OSAKA`，商业部分为 `KITTE大阪`。当前未核实统一的业主官方中文译名；项目中文显示名可另行约定，不能标注为官方译名。业主来源：<https://www.jp-re.japanpost.jp/properties/jptower-osaka.html>。
