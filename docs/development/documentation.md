# 文档维护规范

## 单一职责与归属

- `docs/README.md` 只作索引；根 README 负责运行与交付，不重复区域细节。
- Roadmap 只保留当前状态与剩余任务，完成的流水记录不持续追加。
- `design/areas/` 描述跨板块关系；`stations/` 负责构内依据；`public-areas/` 负责公共面；`buildings/` 负责造型与接入。
- `development/` 负责开发约定；`docs/data/` 负责来源评估和审计。原始文件、哈希和直接事实登记在 `references/catalog.json`；派生资源及重建命令仍放 `data/`、`scripts/` 的就近 README。

不要为每次提交创建文档或为每个小函数拆文件。已有领域内新增小节即可；复杂到需要独立来源、边界和维护入口时再拆分。

## 设计文档应包含

1. **范围与归属**：区域、层级、板块及现役源码入口。
2. **资料事实**：原文件链接、版本或 catalog 条目、页码／对象，以及能直接确认的关系。
3. **当前实现与拟合**：坐标基准、简化方式和人工估计，不能把模型值描述为实测。
4. **未确定项**：区别缺资料、未建模、未核实授权和未做人工验收；具体待办链接 Roadmap。
5. **验证入口**：可重建脚本、相关测试领域，以及检查不能证明的内容。

几何相邻不是入口，图上同层不是实测共面，公开文件不是改编授权。中文说明与源码中的英文注释各自保持一致；界面文案由 i18n 管理，不从文档复制到源码。

## 更新与删除

只更新受影响领域。参数以现役配置为准，文档只保留解释它的依据与约束；失效路径、旧版本 UI 和已完成迁移流水及时删除或概括。少量有核对价值的历次修正可留在所属领域，但必须标明历史语境，不能覆盖当前实现。

不保留独立 `archive/`：旧方案和旧坐标实现通过 Git 历史追溯。删除前检查其中唯一的来源、设计约束和未决项，先并入现行文档，再修正全部引用。原始参考文件不属于文档垃圾，不随文档治理删除。

## 格式与检查

文件名用英文短横线，标题和说明默认中文；使用相对 Markdown 链接。根目录相对源码路径用反引号并说明基准，勿混用退役模块名。目录结构用 tree，说明归属而非穷举所有文件。

移动文档时同步更新根 README、AGENTS、区域索引、源码旁 README、数据及脚本说明和必要的源码注释。检查本地文件及目录链接、残留旧路径、命令路径、`git diff --check`，不把失效链接保留成重定向空壳。外部链接若未重新访问，说明本轮仅检查引用迁移，不宣称完成外部来源再核验。
