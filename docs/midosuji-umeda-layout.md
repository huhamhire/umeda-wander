## 对现有模型的必要调整

1. 引入站点或建筑归属：例如 `jr-osaka`、`osaka-metro-umeda`、`south-gate-building`，楼层使用该归属下的标识；渲染标高与对外楼层名称分开。
2. `Evidence` 增加来源文档身份，设施详情按各自文档显示页码；当前默认 JR PDF 的页码不能用于 Metro。
3. 物理同标高可并列显示，不能仅按 `B1F` 或 `B2F` 名字归并层。聚焦某一站厅时，邻区连接作为参照。
4. 跨运营方路线必须经过 JR 出闸、公共连接、Metro 入闸。加入站点与付费区身份，当前单一“允许付费区”开关不足以表达换乘。
5. 延续独立设施端点、真实开口、半透明井道、楼板外缘连接与几何测试；无障碍路线另加设施可通行能力，不能直接复用仅含扶梯的路线。

实现顺序建议：Metro 内部结构 → JR 接口位置/高程校准 → 双闸口换乘路线。当前视觉风格和 TypeScript/Three.js 技术栈可继续使用，无需先引入新的渲染引擎。
