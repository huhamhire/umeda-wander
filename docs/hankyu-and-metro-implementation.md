## 领域与呈现边界

- 每个站点具有独立楼层身份。Metro 仅使用“站厅 / 中间层 / 站台”对外标签，示意 Y 值为 -8/-12/-16；这不是已核实的 B1/B2 层高。阪急为 1F/2F/3F，示意 Y 值为 0/8/16。
- `stackIndex` 决定分层展开偏移，新增楼层不改变 JR 原有展开位置。内部开口只处理相同站点的楼层；聚焦只保留本站下层，地区总览可显示三站。
- 站台补充终端车挡、单侧轨道、线路色标和屏蔽门样式。阪急九轨旁的最外侧降车带没有伪造第十条轨道。线路色与付费区色分开管理。
- 按用户最新要求，阪急以浅灰粉、淡栗红为轻量主题，付费区、闸机与围栏均保持浅色；京都线绿、宝冢线橙、神户线蓝继续保留。Metro 以线路红作为小范围标识。调色属于呈现层。
- `Evidence.source` 分别使用 JR、阪急 SVG 与 Metro 资料。设施详情不再将所有页码都称作 JR 图。
- 每站数据位于自己的基础设施文件，`station-draft.ts` 负责将局部平面数据变换到示意地区位置，`umeda-map.ts` 组装三站。

## 相对位置与站间接驳

新增区域按阪急位于 JR 东北、Metro 位于 JR 东侧的关系放置。局部北向由既有 JR 示意方位框架换算，尚未对两站重新提取 OSM 轮廓；原点、长度与角度不代表地理校准结果。

阪急保留 JR/Yodobashi 方向的 2F 公共接口，Metro 保留中北西改札外的 JR 御堂筋口接口。它们只表达待接驳的边界，尚未与 JR 路由图连边。跨运营方换乘必须后续经过出闸、公共通路及再次入闸，不能用相邻的付费区相互直连。

## 导览与验证

原右侧导览并入左侧第二个 Tab：第一页“楼层”，第二页“设施”。顶部站点选择在两页中共用；地图点选设施后自动进入第二页。支持点击、左右方向键、Home/End，保留 `tablist/tab/tabpanel` 关系与键盘焦点。手机上使用单面板滚动，不再占据地图右侧。

自动检查包括三站 ID/资料归属、楼层展开稳定性、跨站隔离、全部新增设施落点、改札边界、开口归属、裁剪几何、模型有限值、两条站内路线及 Tab 点击/键盘行为。类型检查、构建与 HTTP 资源检查另行执行。遵循用户要求不操作浏览器，因此视觉、实际帧率与触屏体验仍需用户预览。
