# 阶段四：公共二层连廊装配

更新：2026-11-17。主要已定位连廊接入当前 H5；端点拟合与人工浏览器验收边界另列，不将本轮称为所有重构阶段完成。

## 已接入范围

| 独立板块 | 本轮装配 |
| --- | --- |
| `public-areas/north-decks/` | Grand Front 南北馆直桥、Grand Front—北中庭、Yodobashi 西／东桥与外圈回廊、LUCUA／JR 公共廊至阪急接口 |
| `public-areas/south-decks/` | JP Tower—大丸前庭、梅田新步道桥北／南支臂及沿路主干、阪急百货西侧两个接入口、阪神百货和南出口直梯接入、东南延伸 |
| `public-areas/west-decks/` | LUCUA 1100 西侧公共廊至梅北上方公共步道；不绘对侧建筑，不接地下付费站台 |
| `west-decks/inogate.ts` | 独立 Inogate 2F 公共前沿及西端至 Grand Green 南馆连桥；两端只补平面占位 |

线位来自前期 `data/geography/elevated/` 三份配置及仓库 OSM 快照，实际桥面宽度仍为 6–7 m 示意。运行时截取 34 条已登记步行轴线，保存原经纬度、标签和版本；其中 Yodobashi 外环改用建筑宿主的边界退让环面，避免重复绘制轴线带。其余轴线及四处明确编写的局部接口形成原有 31 条路径，本轮新增 Inogate 两条人工拟合路径，共 33 条。OSM `level=1` 不直接转换成建筑 1F。

另有十二个目的建筑的二层轮廓占位与平面名称：隐藏上层外壳后仍能辨认连接对象，随地面建筑显示控制隐藏；占位不表示可通行商场内部。它们复用 `application/building-occupancy.ts`，减去公共面、车站楼板和设备孔洞，地下占位通过原适配入口保持不变。

桥面在分支处先做并集，再减去同高车站楼板、付费区和前序公共板块；相邻面只保留一个所有者。独立车站仍由原工厂构建，没有把总图反向导入站点模块，也没有增加跨站 RouteEdge。

## 标高与开口

- 北侧用 `district-north-deck`，y=8、stackIndex=2，与 JR 北门大楼 2F、阪急 2F 对齐。
- 南侧用 `district-south-deck`，y=4、stackIndex=1，与大丸较低的前庭 2F、阪神 Deck 对齐。探索层均为 2F，但不声称两侧物理等高；北侧没有直穿 JR 站台连接南侧的新公共桥。
- 北中庭保留已有开放天井和 2/3、47/48 的外缘连接。新桥面同样减去天井，26 号参考直梯的米制落点放在东侧楼板边缘，避开井空；设备点位为拟合。
- 大丸南侧保留弧形退避，西／东连接分别接到已有前庭的两侧，不以一条新楼板封住中央开敞区。50/T、61/U 和东侧双排扶梯继续由 JR 独立维护，未重复创建。
- 共补九组公共设备：北侧参考 26/28 直梯，南侧参考 6/7/8/9/21 直梯，JP Tower 2F 接入处楼梯／直梯。编号仅为资料索引，内部 PUB 编号不在菜单显示。各端点均有公共面承载，电梯竖直，上层楼板和地面遮盖共用真实开口。

南侧原参考图中 62 指向 B1，不将它当作 1F↔2F 扶梯添加。JP Tower 本轮只补有依据的地面↔二层接入；地下门位仍沿用阶段三待核对清单，不通过本轮连桥推断 B1 已贯通。

## Yodobashi 和建筑门口

原外壳中的回廊副本已移除，公共回廊随 2F 楼层独立显示，关闭建筑轮廓也保留。内侧采用沿边界约 5 m 的退让面，避免围绕中心缩放时在凹角形成零宽断口；多边形布尔输入以毫米取整稳定计算，这不是毫米级数据精度声明。裙楼低层轮廓同步避让该回廊。

共登记 14 个明确目标接口；它们是参考计划中的指定对象，不用最近建筑自动认领。Yodobashi 两端接的是外环而非内层墙体；LUCUA 西桥先到 JR／LUCUA 侧公共廊，不把原始 OSM 端点误作零售墙面门洞。阪急站校准后的接口比原 OSM 廊端偏北，沿西侧公共前沿编写局部延伸，保持付费区避让；该延伸的位置与宽度仍是估计。

商业门口的低层外壳、层带和竖向装饰按指定接入范围留缺口，不能只让桥面撞到实体墙上。JP 入口楼梯及贴着阪急／阪神门口的公共直梯另有明确宿主绑定，从地面到桥面留出完整通道，不只在上层切一扇门。栏杆沿公共面暴露边界绘制：细横杆、浅色、约 0.9 m 密柱；同高续接、T 形交汇、建筑门口及设备上端留口。地下板块不复用这套栏杆。

已画出目标的连桥不添加浮动名称；只保留梅北上方北侧与南侧东南端两处未画目标延伸的去向标签。标签引用已存在桥面，不再生成一份桥面模型。

## 来源与可重建结果

- `references/Umeda Walkway Maps/umeda-elevated-walkways-2026.pdf` p1 右图：高架系统、商业接入及公共直梯关系。文件名年份不证明发布版本。
- `osaka-station-city-2f.png`、`osaka-station-city-3f.png`，以及 JR 构内图 p2–5：北中庭、南侧前庭、50/T 与不同去向的设备。
- `jr-west-umekita-decks.pdf` p1／4：梅北步道及 Inogate 新桥的不同目标。
- 仓库 OSM 经地面统一原点投影；只摘取已登记的高架步行线，不重新采集在线数据。

`node scripts/geography/build-elevated.ts` 重建 `data/geography/elevated/ways.json`。修改地区配置时运行它，再执行 `node scripts/geography/review-stage-four.ts`，生成：

- `build/geography/stage-four-overview.svg` 和 north／south／west 局部 SVG：道路、公共桥面、既有车站公共面、付费区及接口；蓝点为新增设备、红圈为指定接口。
- `stage-four-audit.json`：板块、接口公共落脚与目标距离、设备和待定位项。距离只是核查，不创建门洞或路线。

类型检查、230 项测试与构建通过。回归覆盖共用节点去重、同高楼板避让、两组 2F 展开、外环完整性、设备真孔洞、建筑门口裁空、栏杆接缝及稳定设施编号。北／南／西离线 PNG 已查看；未直接操作浏览器，WebGL、手机触控、文字遮挡和真实门口观感仍需人工复核。

同条件 Node v24.18.0 / Windows 离线 CPU 构造约 742 ms，12,501 Mesh、约 103.6 万三角形；阶段三约 612–633 ms、12,139 Mesh、约 92.6 万三角形。该数据不含文字、GPU 和交互，不能视为 H5 首屏或帧率。可用 `profile-scene.ts --output=stage-four-profile.json` 复测。

OSM 原始轴线及估计宽度随 OSM 下载提供；公共平台、建筑裁口、设备和参考层级的混合结果不重新标为 ODbL。参考图整理的授权待核实状态没有改变，见 [来源核查](./source-credits-audit.md)。原始 references 保持不变。

## 剩余事项

1. 桥宽、部分公共设备、阪急西侧前沿和具体商业门口需要人工局部反馈；没有测量净空或完整无障碍核验。
2. 阶段三遗留的三处建筑地下门位、独立出口和局部层高仍按原清单跟进，不把二层连桥连通当作地下验收通过。
3. 真实浏览器／手机整体验收尚未执行；旧 `umeda-map.ts` 仅兼容历史样板，当前 H5 没有再次切回旧坐标装配。

## 2026-11-17 配色与 Inogate 收尾

公共高架桥面统一使用暖赭色 `elevatedPublicColor`，与浅色商业占位分开；细浅栏杆、付费区主题及区域灰化规则保持。离线平面图使用同一个 areaColor，不再以核查专用蓝／棕色替代实际展示颜色。

Inogate 新桥采用 `data/geography/elevated/inogate.json` 与独立 `inogate-decks` 板块。JR 发布资料第 1 页位置图、第 4 页两端及楼层说明，与两份本地 2F 图、OSM Inogate／Grand Green 南馆 Gate Tower 外围轮廓联合拟合：从 JR 北侧 2F 公共面接 Inogate 前沿，再从西端朝西北接南馆。它与更北面的 LUCUA—Green Place 连桥保持独立，不误接 Grand Front 或梅北付费站台。

两端坐标、7 m 桥宽及北侧统一展示标高仍是参考拟合，不是实测门位；两处宿主只显示 2F 平面占位，无商场内部路线、上部建筑或新增跨站 RouteEdge。公共面避让占位、孔洞、同高楼板和付费区，已检查 JR 至目标处的连续公共分量；入口栏杆按声明的门户留口。新桥的细部门口和实际标高继续纳入人工复核。

本批验证：239 项测试、类型检查、构建与差异检查通过。新增检查覆盖 Inogate 至 JR／目标公共分量、宿主避让、地面覆盖范围、道路中段和同名分段接续、真实孔洞。已查看更新后的西侧及地面范围离线图；未操作真实浏览器或手机。
